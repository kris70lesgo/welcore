# ADMS Dispatch demo video

Record a public video under two minutes at the deployed Serverpod Cloud URL. Keep fictional simulation data on screen and narrate the feature flow in English. The hackathon rules accept YouTube or Vimeo links.

## 100-second shot list

| Time | Show | Say |
|---|---|---|
| 0–10 sec | Open the hosted app and start the dispatch demo. | “ADMS Dispatch is a Serverpod-powered ambulance coordination workspace.” |
| 10–25 sec | Point to the live incident queue, map, and three available units. | “Dispatchers can see open incidents and fleet availability together.” |
| 25–42 sec | Create an example incident and show it appear in the queue. | “A new report becomes a persistent incident with an audit trail.” |
| 42–58 sec | Dispatch the nearest unit; show the assigned call sign and availability change. | “The backend ranks available crews by distance and claims a unit safely.” |
| 58–78 sec | Advance the response status and show the activity timeline update. | “The crew’s response progresses through validated stages, with live updates.” |
| 78–92 sec | Open a second tab if time permits, or show the completed incident and returned unit. | “PostgreSQL and Serverpod preserve the shared response state.” |
| 92–100 sec | Show the source repository and Serverpod logo/architecture briefly. | “Flutter is the client; Serverpod provides typed APIs, persistence, and real-time updates.” |

## Before recording

1. Open the hosted URL from `docs/SUBMISSION.md` in a clean browser tab.
2. Start the private demo simulation; no real patient details are needed.
3. Use **Fill example incident** so the flow stays quick and fictional.
4. Dispatch the nearest unit and show the audit/activity update.
5. Keep the recording comfortably below 120 seconds, publish it publicly on YouTube or Vimeo, and paste that URL into the BuilderBase submission.

If the app is idle or still loading, wait for its live indicator before recording. Avoid showing sign-in credentials, recovery codes, or the cloud console.
