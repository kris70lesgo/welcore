# ADMS interface system

Applied installed frontend-design and ui-ux-pro-max skills, plus the existing ADMS design guidelines. Keep the full app in one coherent dispatch workspace.

Direction: a calm operations console with navy navigation, teal actions, white panels, a geographic map, restrained borders, and locally bundled Manrope typography. Readable type, generous form spacing, persistent connection feedback, and clear response stages take priority over decorative effects.

Use a 4/8/12/16/20/24/32 spacing scale; 12px control corners, 16px panel corners, and 20px dialog corners. Interactive controls have at least 48px touch targets. Text fields show visible focus, labels, validation, and saving states. Read-only or prohibited actions are hidden or disabled according to server-derived roles.

Desktop: scrollable navigation, operational KPIs, map/queue, and response panel. Mobile: compact section selector and stacked content; crew response controls precede the map. Every section includes an empty state. Connection errors preserve the last snapshot, and an intake draft survives reloads in the same account session.

Role journeys: administrator organization setup and enrollment; dispatcher intake and assignment; crew location, patient documentation and handover; citizen report and tracking. All labels describe actual actions. Enrollment and recovery codes are one-time and displayed explicitly for private sharing.
